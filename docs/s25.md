OneiOS began on the Galaxy S24 Ultra (SM-S928, SM8650). This is the second target: the **base Galaxy S25, SM-S931B,
codename `pa1q`, SM8750 ("sun", Snapdragon 8 Elite for Galaxy)**. Two firmware generations are recorded here: One UI 8.5
`S931BXXSBCZG3` (Android 16, the build the fork's probe ran on) and One UI 9 `S931BXXUCDZIF` (Android 17 / OS17,
the build this tree was checked against from its shipped boot image; firmware 2026-09-20, kernel built
2026-09-19). The design does not change (XNU runs as a process, xnuhost, on One UI's kernel); what changes is the host it meets. Marks: [F] read from a source named
beside it, [I] inferred, [U] unknown until the probe has run on the phone.

## What was changed for the S25

| Area | Change |
|---|---|
| Display | **In the s25ver snapshot, not in this tree as such** (that snapshot made 1080x2340 the default of every fallback, which would change the S24 Ultra's). Here (2026-11-21): xnuhost takes the panel's mode from the display helper's report or the DRM panel, so an S25 session gets 1080x2340 without a setting; only where no panel is read does it assume a size, and `--set panel-fallback=1080x2340@120` (or `panel-fallback=` in the image set's `xnuhost.conf`) makes that the S25's instead of the S24's 1440x3120 (same aspect ratio, 1.78x the pixels, scaled down every frame; [booter.md](booter.md) 2.8). The display helper's last fallback is its existing `--logical 1080x2340` (passed by the OneOS fork's switch script, not here); `displayctl test --size 1080x2340` for the bench; the guest profile `userland/config/device-iphone18,2.toml` stays 1440x3120 (it only feeds `oneios-mg`'s expectations, which then report `identity=differs` on a 1080 panel: a log line, nothing waits on it). With the S25's panel the UI scale stays 3: **360x780 points**, the pixel grid of the iPhone 12 mini / 13 mini; `--scale 2` gives 540x1170. A point is 1/139 inch (the iPhone's 1/153): 44-point targets are 8.0 mm. The artwork set stays the Pro Max's (`artwork-device-subtype` 2868, its assets are certainly in the image); the 12/13 mini's subtype (2340) is an untested alternative [I]. `test_xnuhost` and `test_display_mode` cover `panel-fallback=`. At 1080x2340 a frame is 10.1 MB (18 MB before). |
| CPU plan (`runtime/bridges/cpu/topology.rs`; `topology.c` then) | Oryon has no little cores. The old rule (lowest capacity = E) would have made the six performance cores an E cluster and left iOS two P cores. Now a Qualcomm core (MIDR implementer 0x51) is never E, and a host whose cores are all P but of different speeds **lends** its slowest cores to the guest as E vCPUs (one in four vCPUs, at least one; 8 vCPUs: 2 E + 6 P), because XNU's AMP scheduler and the iPhone's boot CPU want both kinds. Hosts with all-alike cores and the S24's A520 cores behave as before. Tests with an SM8750-shaped fixture (made-up capacities and frequencies, the real shape): `runtime/bridges/tests/test_bridges.c`, 210 checks. |
| Phone gate in the OneOS fork | The fork only offered iOS on the S24 Ultra, in two places: `OneiosSystem.PROFILE_IDS` (Kotlin) and the preflight of `switcher/assets/oneios_switch.sh`. Both now accept `SM-S931*` / `pa1q` / `SM8750` as well (the fork already has the S25 profile `s-8750`). Its tests and the refusal texts follow. The fork's tests were not run here (Gradle); the workflow `oneos-apk.yml` runs them. |
| Metal translation | `userland/metal/patches/metal2vulkan/` holds the Adreno-generic shader-translation fixes of hakios-arm64e-dada (see below), rebased on the pin; `userland/metal/build.sh` stages them as `9xxx` patches after the base's own. |
| Wi-Fi supplicant version | The base S25's image serves `ISupplicant` version **3** (the S24 Ultra's serves 2). `runtime/bridges/wifi/supplicant.rs` now reads `getInterfaceVersion` and reports it in `wifictl status` and (when above 2) in the log; every call it makes is a version 2 one, which version 3 kept. The binder stand-in (`runtime/bridges/tests/test_aidl_binder.rs`) serves version 3, so the host test proves the client against the base S25's shape. Not run on the phone yet. |
| GPU (Adreno 830) | Covered by the Ultra bring-up below: the `0007-a830-waittimestamp-fences` default is chip-independent, and the A830 stand-in test uses the base S25's shape (chip `0x44050000`, gpu_id 6850, 12 MiB gmem, 192 GiB VA, the 128 GiB VBO rung). Nothing is gated on the model: an A750 behaves as before (`WAITTIMESTAMP_CTXTID` was already the default outside A830). |
| Phone probe | `tools/probe/s25-probe.sh`: read-only; writes `/data/local/tmp/oneios-s25-probe-<time>.tar.gz`. |

The snapshot's `s25-phone-kit.yml` is **not** in this tree: CI here is the one `release.yml` workflow (runtime + APK); the kit was the runtime package plus `tools/probe/s25-probe.sh`, both of which a tester gets from a release and from this tree. |

Host fixes, all S25-gated (S24 behavior unchanged):

1. **Adreno 830 fence default** (`runtime/xnuhost/drm2kgsl/patches/0007-a830-waittimestamp-fences.patch`):
   on SM8750 the `KGSL_TIMESTAMP_EVENT(FENCE)` path SIGSEGV'd userspace after the first `GPU_COMMAND`
   (`gpuctl submit`, xnuhost backboardd). The default is now the `WAITTIMESTAMP_CTXTID` path everywhere;
   `NCTX_NO_WAITTS=1` forces the FENCE path for A/B only. Applies after our `0001`–`0008` drm2kgsl patches
   (verified with the C Makefile's own `patch --forward -F0` loop; `runtime/xnuhost/drm2kgsl/build.rs` applies them the same way today); the branch's copy lacked its trailing
   newline, fixed on port. Full kernel build still wanted; `git apply --check` equivalent is the loop above.
   `test_drm2kgsl` (now `runtime/xnuhost/src/gpu3d_kgsl/tests.rs`) has an A830 profile (chip 0x44050000, gpu_id 6850, 12 MiB gmem, 192 GiB VA): it checks the
   128 GiB VBO rung (256 GiB leaves no import room) and that the timestamp path is the default while
   `NCTX_NO_WAITTS` asks for `TIMESTAMP_EVENT(FENCE)` (10 checks).
2. **`virgl_fence_table_init()`** in `runtime/xnuhost/src/gpu3d_kgsl.c` (now in drm2kgsl's glue, `runtime/xnuhost/drm2kgsl/glue/oneios_glue.c`): the fence table was never
   initialised (the full virglrenderer init is not linked into xnuhost). `virgl_fence.c` was already in
   `DRM2KGSL_SRC`, so this is one include plus one call on the existing open path.
3. **`--forward`** in the `drm2kgsl/patched` Makefile rule: re-running the build no longer fails on an
   already-patched tree (`drm2kgsl/build.rs` patches a copy in cargo's `OUT_DIR`, with `--forward` too).

Not taken from the branch, and why: its `topology.c`/`test_bridges.c` predate our merged Oryon work
(16 Nov vs commit `72b92f6` — no implementer-`0x51` check, no E-lending; ours stays); the `ONEIOS_XNUHOST`
`config.h` line guards nothing on our virglrenderer pin (no consumer in the pin's `drm_fence.c`, and the
fence-export path it would skip is already avoided by fix 1); its Makefile hunk deleting the xhd-based
`test_display_mode` and the `rpc-arm64` bench predates those targets here; its README reframes the repo as
the fork (that mapping lives in [forks.md](forks.md)).

Phone-side scripts (plain POSIX shell; the embedded exact-match patcher in `build-dropbear.sh` is a frozen
heredoc, `python3 -m py_compile`-checked, not a new tool):

- `scripts/port/verify-host.sh`: read-only preflight; since 2026-11-21 it accepts the S24 Ultra, the S25 Ultra, the base
  S25 (`SM-S931`/`pa1q`/`SM8750`) and the A56, model, codename and SoC as one row, and exits 2 on anything else;
  prints KGSL chip id, udmabuf limits, CPU count. Host test: `scripts/port/test-verify-host.sh`.
- `scripts/phone/ssh-forward.sh start|stop|status`: phone-side busybox-`nc` relay
  `127.0.0.1:7222 -> 192.168.77.2:2222` plus `adb forward tcp:2222 tcp:7222` to the guest's dropbear (wifi=tap).
- `userland/helpers/build-dropbear.sh [OUT]` / `build-zsh.sh [OUT]`: arm64e dropbear 2022.83 (pubkey-only,
  fixed shell `/private/var/oneios/bin/zsh`, fixed authorized-keys path) and arm64e zsh, signed, 4 KiB pages,
  for the helpers output dir that `oneios-tool image tweaks apply --helpers` installs (see `userland/helpers/README.md`).
  macOS + iOS SDK + network; not built here.

Fork-claimed device results (not re-run here): `gpuctl submit`/`large` pass on SM-S938B; sessions with a
fork-built `xnuhost` reached SpringBoard; logo-only stalls traced to bad overlays (custom `boot-args`
replacing defaults, SSH seed/trust-cache drift, stock release `xnuhost`). Recovery: restore tarball
`data.seed`, `owner-trust`, `overlay/userland/xnuhost.conf`, wipe `data.img` only to reset Data. Preflight
can refuse while the battery is hot (~42 °C). Guest Spotlight/indexers can heat long sessions; the image
already disables most of them (`userland/config/daemons.toml` group `base`), and the kernel's
`oneios-disable-jobs=` boot-arg (patch `0053`) covers the rest per boot.

## What was taken from hakios-arm64e-dada, and what was not

## What the first booted session found (2026-11-23, 19:36)

The session booted and ran from 19:35:55 to 19:40:01 (the remount APK, runtime `0.1.21-s25wifi`): display, touch,
brightness, battery, thermal, Wi-Fi (supplicant v3), camera nodes and audio all came up. Five things came out of its log
(`session/xnuhost.log`), and each is answered below.

1. **The GPU: no Metal plug-in in the image, and `backboardd` dies without one** [F]. `oneios-gpu-list` wrote no image
   path (`"*": not written (2)`), `oneios-gpu-addon` failed at stage 1 with status 2 (`/private/var/oneios/addons/
   Extensions` has no source), and `oneios-gpu-open` then showed `backboardd … AGXAccelerator type 0x1 ->
   0xe00002c7`: stock Metal's IOGPU device client, which NativeAdreno refuses (`kIOReturnUnsupported`). The real
   plug-in is opened as type `0x4149`. With a published accelerator it cannot use, `backboardd` aborts in
   `push_surface` (`sheng-exc: exception type=0xa code=0x6000000`) twice (pids 55 and 283), and launchd reboots:

   builds it on a macOS runner (docs/gpu.md 7), and it is staged as a boot addon (`oneios-tool phone addon`) or
   copied from the working S24 Ultra. Until then the session is CPU-rendered and the crash recurs at about 4 minutes.

## Open

- Nothing of OneiOS from this tree has run on an S25. Every [I] and [U] above is a guess until the probe and a first session; the S25 Ultra session claims in the section above are the fork's, not re-run here.
- The hakios **kernel patch** was not audited for Oryon quirks (system registers, errata, PAC key handling, timer).
  Under Linux most of that is the host's business, but the trapped-instruction paths (`runtime/xnuhost/src/sysreg.rs`,
  the `0027` PAC patch) should be read against an Oryon core's behaviour once the probe shows its ID registers.
- hakios's iOS 26 bring-up (`userland/`) was not diffed against OneiOS's iOS 27 userland tweaks.
- Adreno 830's device description is in the Mesa pin (Turnip, `cecc0e9`: the a8xx table names `0x44050000`/KGSL `0x44050001` as "Adreno (TM) 830"), so a plug-in built from the pin is built for it; whether the driver drives it is the first Metal run, and the FENCE path (`NCTX_NO_WAITTS=1` A/B on SM8750) and gmem/udmabuf on the base S25 are the probe's. No PC test can stand in for that run: qemu has no KGSL and no 3D context, so `gpuctl` on the phone and the first session are the only dynamic checks (docs/gpu.md 3, "Not tested on the PC").
- The OneOS fork's phone gates (`OneiosSystem.PROFILE_IDS`, `oneios_switch.sh` preflight) for `SM-S931*`/`pa1q` and
  `SM-S938*`/`pa3q` live in that repo. The S25 Ultra branch's note about the switch and single files is now
  **proven on the base S25** (2026-11-23, the first session there): the inner shell ended at `making
  /data/oneios_switch.sh read-only` with status 70 and `mount: can't find /data/oneios_switch.sh in /proc/mounts`,
